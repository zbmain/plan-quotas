# software｜全站翡翠绿视觉升级与验收

采用翡翠绿品牌色、Instrument Sans + DM Mono、本地 WOFF2、4／6／8px 圆角和统一微交互。页面按工作台内容自然延伸。视觉参考为 [Vercel Geist](https://vercel.com/geist/introduction) 的控件与排版，以及 [Supabase](https://supabase.com/) 的绿色品牌表达。沿用现有真实品牌图标，taste-skill 的 motion.css / motion.js 原样提供交互反馈。

## 实现结果

- 首页使用“订阅状态”和“账号清单”；三项统计在一个面板内等宽排列，数字在上、标签在下。320px 起均为单行，完整显示四位计数，万级采用中文紧凑表示，辅助技术和悬停提示仍提供准确数量。
- 区分真实零值、加载占位和缺失数据。统计读取全部账号，不受搜索、渠道、状态筛选影响。
- 顶栏、正文、页脚统一到 1200px 内容边界，手机左右留白 16px。账户卡片按桌面三列、平板两列、手机一列排列；账号别名与套餐名自然换行。
- 后台、登录页、配置弹窗、输入框、按钮和图表共享深浅主题；手机操作按钮为 44px。主题保留跟随系统与持久化偏好，并在首帧初始化。
- 配置弹窗使用原生 dialog 隔离背景，显式处理 Tab 首尾循环、步骤焦点与 Esc 关闭还焦；正文滚动状态在关闭时恢复。
- 移除卡片错峰淡入和图表入场动画。动态效果集中于真实交互与数据更新；减少动态效果模式下停止位移及动画。
- 四个字体文件合计约 79 KiB，许可随资源保存；页面不依赖外部字体请求。屏外品牌图标延迟加载。

## 工程与浏览器验证

在项目固定的 Node.js 26.13.0 下，完整检查通过：444 项后端测试、67 项前端测试、类型检查、ESLint、Prettier 和生产构建。后续焦点、无障碍标签调整再次通过前端构建和 ESLint。公共 API、数据结构、额度计算和账号可用性规则保持兼容。

Ego 验收使用独立的合成数据预览，没有修改真实账号或调用供应商服务：

- 深浅主题各覆盖 320、375、390、768、820、1024、1440px。三项统计顶边一致、标签完整，页面无横向溢出；账户列数分别为一、二、三列。
- 覆盖空数据（0／0／0）、首次失败（—／—／—）、加载（三格占位）、全部可用（6／6／0）、部分不可用（6／5／1）、长别名和 9999、12345、123456 计数。
- 验证筛选后的统计仍为全部账号；已用 42% 切换后显示剩余 58%；历史趋势正常渲染。
- 验证登录错误与成功、后台操作尺寸、配置弹窗两个步骤、Tab／Shift+Tab 循环、第二步输入焦点、Esc 关闭并返回触发按钮。
- 验证跟随系统明暗变化、减少动态效果，以及四个字体字重实际加载。

## taste-skill 检查与适配例外

最终一致性检查的基础质量项通过，包括对比度、字体加载、文本重叠、裁切、横向溢出、可见区域边界、悬停、motion 层及减少动态效果。本次卡片排版调整后的原始工具结果为 **171 FAIL、15 WARN**，以下全部 FAIL 按已确认的工作台方案归类为适配例外，并未修改检查器或伪报全绿：

性能检查使用三个加载样本的中位数：**0 FAIL、2 WARN**（桌面与手机分别提示已有 JavaScript 包约 667 KiB）。字体体积、请求、阻塞时间、资源加载、布局位移均通过；桌面 CLS 0.016，手机 CLS 0.000。现有 Vite 大分块提示继续保留。
